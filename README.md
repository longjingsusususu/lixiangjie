# 会议活动服务需求汇总 · 需求查询与交接平台

> 仓库 `lixiangjie` ｜ 一个把「会议活动服务需求」从散落文档变成**可查、可确认、可交接、可追责**的结构化系统。
> FastAPI + SQLite + 服务端渲染，一期纯结构化、**零 LLM**，二期限定场景再接入模型。

---

## 1. 这个项目解决什么问题

会议活动服务（会场、餐饮、住宿、设备、注册、翻译……）的需求通常散在邮件、微信、Excel 和几个人的脑子里。一线人员要回答「这场会的双语主持定了吗」「签到台谁确认的」只能靠问人，交接触发点全靠记忆，漏项在活动前一周才暴露。

系统把每条需求变成一条**带状态、带责任人、带来源、带时间戳**的记录，并给出三个入口：

| 入口 | 使用者 | 解决什么 |
|---|---|---|
| 员工问答入口 | 一线（林亦舟类） | 一句话问「餐饮有什么没定」，返回**缺项清单 + 来源位置**，不是泛化摘要 |
| 管理后台 | 协调员 / 业务负责人 / 质量 / 管理员 | 需求项库、批量导入、卡口规则、审计与标记 |
| Agent 编排层 | 协调员 | 多轮自主决策：查清单 → 校验 → 建交接，写操作前**强制人工确认** |

## 2. 五条硬约束（架构由它们决定，不是技术偏好）

1. **一期零 LLM**（客户红线）：检索与汇总全部确定性实现，`MEETING_LLM_PROVIDER=off` 为默认值；开启后仅影响文案汇总，不影响任何判定。
2. **只读集成**：不对服务台/台账写回，不做外部开放接口；系统间无统一编号时靠 `id_mappings` 映射，接口打不通降级 CSV。
3. **五态状态机**：缺失 → 未确认 → 已确认 → 已定版 → 已交接。**缺失**与**未确认**分列统计，不允许混为一谈。
4. **卡口不可绕过**：交接必须同时具备「责任人 + 确认状态 + 来源」三要素，服务端一次性票据校验，提示词层面无法跳过。
5. **模型无审批权**：所有写操作由人确认；确认前零落库（有硬断言测试覆盖）。

## 6. 主要接口

| 接口 | 说明 |
|---|---|
| `POST /api/login` | 员工端登录，返回 JWT |
| `POST /api/chat` | 查询（SSE：`status → item×N → chunk×M → done`） |
| `GET /api/sessions`、`/api/sessions/{id}/messages` | 会话列表与历史（含引用） |
| `POST /api/tools/{name}` | 工具调用（10 个工具，服务端校验前置条件与票据） |
| `GET /api/handover/check` | 交接三要素预检 |
| `POST /api/agent/chat` | Agent 对话（SSE：`run/decide/tool/act/observe/draft/final/done`） |
| `POST /api/agent/confirm` | 写操作确认（票据 5 分钟一次性） |
| `/admin`、`/admin/*` | 后台页面：概览、需求项、导入、规则、审计、工具、用户、Agent |

## 7. Agent 编排（二期形态，已落地骨架）

- **Harness 薄循环**：`decide → invoke → observe`，`MAX_ROUNDS = 5`，超轮收束并如实告知。
- **顺序约束靠服务端，不靠提示词**：`validate_handover` 通过后发一次性票据（绑 item + receiver + deadline 的哈希），`create_handover` 五步验票；伪造、换参、重放、跳格分别返回明确错误码。
- **写操作前强制中断**：`create_handover` 属于 `INTERRUPT_TOOLS`，流式在「决定执行」与「执行」之间断开，等人工 `POST /api/agent/confirm` 才落库。
- **全链路留痕**：每轮 `decide` 一行、每次执行 `act` 一行（含耗时、参数摘要、错误码），管理端可按 run 回放。

## 9. 数据与合规

- `data/demo_会议需求样例.md` 中 18 条需求项为**合成数据**，用于演示解析与检索，不含任何真实客户信息。
- 报价单与三案设计中的金额为方案测算值，非实际成交价。
- 上线前需处理 `docs/05-ops/` 中标注的 P0 项：默认 JWT 密钥、Cookie Secure 属性、数据库备份、对话限流、登录失败锁定、提示词注入防护、版本快照、回滚预案。

## 10. 已知限制

- 单机 SQLite，未做多实例部署与读写分离；并发上限见上线检查清单 B 组。
- 检索为 BM25 + TF-IDF 融合，无外部向量库；语料量级按「单项目数百条需求项」设计。
- 仅面向中文需求文本，同义词表需按项目字典维护（支持后台热更新）。
