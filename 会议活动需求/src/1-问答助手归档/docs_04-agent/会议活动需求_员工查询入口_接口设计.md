# 会议活动需求 · 员工查询入口 · 接口设计（待确认稿）

> 角色：FastAPI + 前端全栈工程师 ｜ 主题：**会议活动需求**
> 与报销版的三个差异（主线约束）：
> ① 检索对象是**需求项**（阶段 1 已建好的 HybridRetriever），不是制度文档切片；
> ② 回答形态是**缺项清单 + 来源位置**（f15），LLM 汇总为可选开关（一期默认 off，f01）；
> ③ 每次查询写**留痕四项之一"谁查过"**（f44），这不是可选项，是验收口径的一部分。
> 存储沿用阶段 1 形态：SQLite + 阶段 1 的表结构，新增需求项表与留痕表。

## 1. 接口清单

### 1.1 POST /api/chat —— 员工查询（SSE 流式）

**请求**（Bearer JWT，登录后携带）

```json
{
  "session_id": "uuid 或 null（null=新建会话）",
  "question": "双语主持相关的需求有哪些？"
}
```

| 校验规则 | 失败返回 |
|---|---|
| 未登录 / token 失效 | 40101 未登录或登录已过期 |
| question 为空 | 40001 问题不能为空 |
| question 超过 200 字 | 40002 问题过长（上限 200 字，需求查询不需要长文） |
| session_id 不存在或不属于当前用户 | 40401 会话不存在 |
| 10 秒内同一用户第 6 次请求 | 42901 请求太频繁，请稍后再试 |
| 检索索引未就绪（需求项未加载） | 50301 检索索引未就绪，请联系管理员导入需求项 |
| 其他未捕获异常 | 50001 系统繁忙，请稍后重试（中文信息统一返回） |

**响应**：`text/event-stream`，事件序列如下（前端按事件类型分别处理）：

| 顺序 | event | data 示例 | 前端行为 |
|---|---|---|---|
| 1 | `status` | `{"stage":"search","message":"正在检索需求项…"}` | 状态条显示打点动画 |
| 2 | `item` ×N | `{"item_no":"LS-02","category":"语言服务","status":"未确认","content":"主持人临时改为中英双语主持","owner":"唐映秋","source_tool":"手工补录","source_ref":"群消息2026-10-24\|聊天记录"}` | 每命中一条，清单追加一行（表格卡片） |
| 3 | `chunk` ×M | `{"text":"共命中 3 项，其中未确认 2 项。"}` | 打字机效果逐字上屏（规则生成的汇总文案；LLM 开启时为模型输出） |
| 4 | `done` | `{"session_id":"…","message_id":123,"elapsed_ms":86,"citations":[{"source_tool":"服务台","source_ref":"SD-2026-0112｜第3行","snippet":"无线手持话筒 4 支"}]}` | 底部渲染引用来源；解锁输入框 |
| 任意 | `error` | `{"code":50301,"message":"检索索引未就绪…"}` | 红色错误条；解锁输入框 |

**为什么仍然用 SSE**：一期虽然默认无 LLM，但 SSE 让"检索中→逐条出结果→汇总"有渐进体验，且二期接 LLM 时前端零改动——只是 `chunk` 的内容从规则文案变成模型输出。

### 1.2 辅助接口（3 个）

| 接口 | 方法 | 说明 | 主要错误码 |
|---|---|---|---|
| /api/login | POST | 用户名密码 → JWT（阶段 1 同款） | 40102 用户名或密码错误 |
| /api/sessions | GET | 当前用户的会话列表（侧栏历史） | 40101 |
| /api/sessions/{id}/messages | GET | 单会话全部消息（点开历史回看，含引用） | 40401 |

管理员侧"看记录"复用 messages + audit_logs，本期不做管理页（避免范围膨胀）。

## 2. 数据表（SQLite，沿用阶段 1 形态 + 两张会议表）

| 表 | 来源 | 关键字段 |
|---|---|---|
| users | 阶段 1 同结构 | id / username / password_hash / display_name / role（本期 staff 登录即可，字段留五角色枚举） |
| chat_sessions | 阶段 1 同结构 | id(uuid) / user_id / title(首问截取) / created_at |
| messages | 阶段 1 同结构 + 1 字段 | id / session_id / role(user/assistant) / content / **citation_source_refs(text，JSON 数组：[{source_tool,source_ref,snippet,item_no}])** / latency_ms / created_at |
| requirement_items | 新增（阶段 1 解析结果落库） | item_no / category / content / status(五态) / owner / source_tool / source_ref / biz_occurred_at / received_at |
| audit_logs | 新增（留痕四项最小版） | actor_id / action(view) / target_type="item" / target_id / created_at —— f44"谁查过"就靠它 |

> 说明：阶段 1 的检索器直接吃 requirement_items 内存列表，落库后启动时从 SQLite 加载，行为不变。

## 3. 上下文策略：最近 6 轮

每次 /api/chat 取当前会话最近 6 条消息（3 轮问答），用途两处：

1. **一期（规则版）**：查询扩展——历史里最后出现的类别词（如上一问提到"语言服务"）与同义词表一起拼进当前查询，支持"那餐饮呢？"这类**省略式追问**；
2. **二期（LLM 版）**：原样拼入提示词，接口与表结构不变。

## 4. 前端单页（HTML + 原生 JS，一个文件）

```
┌────────────────────────────────────────────┐
│  会议活动需求查询台          [当前用户·退出]   │
├──────────┬─────────────────────────────────┤
│ 历史会话  │  [用户] 双语主持相关的需求有哪些？  │
│ (侧栏)    │  ⏳ 正在检索需求项…               │
│          │  ┌─────────────────────────────┐ │
│ ·XX年会   │  │ LS-02 语言服务 未确认        │ │
│ ·10月周会 │  │ 主持人临时改为中英双语主持     │ │
│          │  │ 责任人:唐映秋 来源:群消息10-24 │ │
│          │  └─────────────────────────────┘ │
│          │  共命中 3 项，未确认 2 项。█(打字机)│
│          │  ── 来源 ────────────────────    │
│          │  ① 手工补录｜群消息2026-10-24     │
│          │  ② 服务台｜SD-2026-0118｜第12行   │
│          ├─────────────────────────────────┤
│          │  [输入框…            ] [发送]     │
└──────────┴─────────────────────────────────┘
```

要点：
- `fetch` 读 SSE 流（`ReadableStream` 手动解析，兼容性最好），按 event 类型分发；
- 打字机：`chunk` 文本进缓冲区，`setInterval` 逐字上屏（25ms/字），`done` 时清空定时器；
- 状态条：收到 `status` 显示"正在检索需求项…"+CSS 打点动画，收到首个 `item` 即隐藏；
- 引用区：`done.citations` 渲染，格式"来源工具｜单据号｜原始行位置"（f15 要求的来源定位）；
- 错误处理：`error` 事件与非 200 响应统一弹红色横条，显示后端中文 message，输入框解锁；
- 会话历史：侧栏调 /api/sessions，点击回看调 messages 接口。
