## 一、报价说明与依据

本报价对应**已确认的技术架构基线**（十个关键问题于 2026-11-06 经项目发起人确认"全按推荐"）：自研轻量 Web 单体（FastAPI SSR + SQLite）、数据入口三路留口子（接口/CSV/手工）、系统版本号 + 手动定版、拦截式交接三要素卡口、异常人工队列（不得默认通过）、一期纯结构化零 LLM（槽位预留）、云部署 + 字段级脱敏、混合指标测量、持续运营轻量后台。

与 v1.0 报价单（QT-2026-1023-01，四阶段 ¥65,000）的关系：v1.0 中 P1 诊断与基线测量（5 人天）、P2 方案设计与 Demo（8 人天）的产出——业务挖掘成果 v3、需求报告、典型事件资料 E-01、行业分析、系统需求分析方案、技术架构选型——**均已交付**。本报价仅覆盖剩余实施工作，故总价区间低于 v1.0 属正常口径差异，并非降价。

三档共享同一架构基线，差异只在**范围深度与智能化档位**，不在技术路线——任何一档升级到另一档都不需要返工或换栈。

### 4.4 敏感性分析（以中档为例）

单场节省实测值直接决定回收期，测算对①②的偏差最敏感：

| 实测单场节省 | 年节省测算（20 场/年） | 中档回收期 |
|---|---|---|
| 15 人时/场（测算口径） | ¥45,000 | 约 14.7 个月 |
| 10 人时/场 | ¥30,000 | 约 22 个月 |
| 5 人时/场 | ¥15,000 | 约 44 个月 |

结论：**若试点前两周实测基线显著低于 f12 口径（回查不足 4 小时），应优先低档或中档**；低档回收期对基线偏差的容忍度最高。这正是 P1 类基线测量不可裁剪的原因（本方案中该项产出已交付，剩余动作是试点首周实测替换假设值，R7）。

### 4.5 效果浮动（可选，各档通用）

沿用 v1.0 的双指标浮动机制：基础报价之外设效果浮动上限 15%（低档 ¥4,500 / 中档 ¥8,250 / 高档 ¥15,000），同时满足两项才支付——① M6 确认完整率 100%（50 项全部具备责任人与确认状态）；② M1 异常回查人时降幅 ≥ 40%。未达则浮动为 0。只挂一项都可能被"降口径达成"，双指标互为约束。

## 五、结算方式

| 比例 | 节点 | 前置条件 |
|---|---|---|
| 30% | 签约启动 | 范围确认书签署（选定档位与模块明细）、测试环境就绪 |
| 40% | 版本交付 | 指定档位功能全部交付并通过冒烟：卡口拦截率 100%（含绕过前端直调 API 用例）、双时间戳可区分、留痕四项可回查 |
| 30% | 验收通过 | 低/中档：50 项验收记录 + 口径文档；高档另含智能化模块验收与运维移交 |
| 浮动 | 效果结算 | 4.5 双指标同时满足，验收后 30 日内结算 |

## 六、报价边界（不含项）

1. 任何写回、对外系统接口开发与账号权限开通（f32 红线，永久不做）；
2. 真实嘉宾邀请、会议安排发布、敏感个人需求确认（f05/f52）；
3. 自动审批、自动定责、任何形式的自动放行（f22：模型/系统无审批权）；
4. 客户侧数据缺失导致的重复测量与返工（超出 32 人时另行报价）；
5. 统一编号方案的跨企业数据打通（三源之外的新系统接入另行报价）；
6. 任何形式的收益承诺（全部节省量为试点目标值）；
7. 低/中档的试点期后运维（移交文档齐备，客户自主接管）。

## 八、选档建议

- **预算刚性或想先验证卡口价值** → 低档：8 个月回收测算口径下风险最小，且后续升档不返工；
