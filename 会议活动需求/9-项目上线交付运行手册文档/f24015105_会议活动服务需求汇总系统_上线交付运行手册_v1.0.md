## 一、手册目的与读者

本手册回答三个问题：**系统怎么交付上线、上线后每天/每周谁做什么、出事了怎么处理**。读者为系统管理员（秦芮）、质量验收（傅景）、协调员（唐映秋）及后续接管运维的技术人员。

手册对应报价中档（标准版）交付范围；低档交付时第 4.3 节"三源接入"与第 5.2 节"配置后台"条目不适用。**所有操作均可在 10 人并发、单批次 50 项规模内完成，不要求专职运维。**

## 二、上线前置条件检查单（全部满足方可上线）

上线闸门分两类：**技术闸门**由实施方自检，**业务闸门**必须由对应干系人书面确认。任何一项未通过，上线顺延，不得带病上线。

### 2.1 技术闸门（实施方自检）

| # | 检查项 | 通过标准 |
|---|---|---|
| T1 | 冒烟测试 | 50 项虚构样本（f12）端到端全绿：登记→定版→卡口→队列→看板 |
| T2 | 卡口拦截率 | 交接三要素缺失 100% 被拦截，**含绕过前端直调 API 的用例** |
| T3 | 双时间戳 | 补录记录的业务发生时间与系统接收时间在统计上可区分 |
| T4 | 留痕四项 | 抽查任意一项，可沿变更历史+审计日志回答"谁查过/哪个版本/什么建议/谁确认" |
| T5 | 权限矩阵 | 五角色越权访问全部返回 403；确认类字段仅业务负责人/质量验收可写 |
| T6 | 无自动通过 | 异常队列全流程无一例默认通过（f44） |
| T7 | 备份恢复 | 完成 1 次备份→恢复演练，数据完整（见第 8 章） |

### 2.2 业务闸门（干系人确认，对应 R1–R6）

| # | 事项 | 待谁确认 | 未确认的处理 |
|---|---|---|---|
| B1 | 交接责任转移时点口径（R1） | 顾明岚 | 卡口字段按两口径并存运行，签字前不锁定 |
| B2 | 版本规则维护人与复核周期（R2） | 顾明岚+傅景 | 定版功能不上线（低/中/高档一致） |
| B3 | 异常队列值守人与响应时限（R3） | 傅景 | 队列功能上线形同虚设，**建议作为上线硬前置** |
| B4 | 三源只读接口能否开放（R4） | 秦芮 | 开不了走每周 CSV 导入，不阻塞上线 |
| B5 | 50 项分批/跨区口径（R5） | 顾明岚 | 影响 M6 分母与编号映射表初始化 |
| B6 | 脱敏粒度与留存期限（R6） | 秦芮+傅景 | 脱敏规则配置位保留为空，敏感需求不入库 |

## 四、环境与部署

### 4.1 环境要求

| 项 | 要求 |
|---|---|
| 服务器 | 1 台云主机或室内服务器：2 核 4G、40G 磁盘即可（50 项/10 人规模） |
| 操作系统 | Linux（推荐）或 Windows Server 均可 |
| 运行时 | Python 3.11+；依赖仅 fastapi、uvicorn、python-multipart |
| 数据库 | SQLite（WAL 模式），零安装；后续可平迁 PostgreSQL（换连接串） |
| 网络 | 企业内网或 VPN 可达；启用 HTTPS（反代或证书直挂） |
| 备份 | 每日自动备份任务（见第 8 章）+ 异地留存 1 份 |

### 4.2 首次部署步骤

```
1. 解压应用包至 /opt/meeting-app（Windows 任意目录）
2. python -m venv .venv && 激活虚拟环境
3. pip install -r requirements.txt
4. 设置环境变量：
   MEETING_MVP_DB=/opt/meeting-app/data/meeting.db     # 数据库文件路径
   MEETING_MVP_SECRET=<随机生成，≥32字符，妥善保管>       # JWT 签名密钥
5. python manage_init.py                              # 建库建表
6. python manage_users.py create <账号> <角色>          # 创建五角色账号（见 7.1）
7. uvicorn app:app --host 0.0.0.0 --port 8800 --workers 2
8. 浏览器访问 https://<地址>:8800/login 验证登录
```

### 4.3 三源接入配置（中档/高档）

| 数据源 | 接入方式 | 失败降级 |
|---|---|---|
| 服务台 | 只读接口，配置于 config（地址/凭据由秦芮提供） | 自动降级：保留上次快照并标记时间（f35），管理员改走 CSV 导入 |
| 台账 | 同上，需先完成字段对齐表 | 同上 |
| 文件库 | 只读版本快照核对 | 同上 |

**接口开放性未确认（R4）期间一律使用 CSV 导入**：管理员每周固定时间导出三套工具数据→系统"导入"页上传→系统自动按编号映射表关联（f30）。导入幂等：同批次重复导入不会产生重复项。

### 4.4 启动 / 停止 / 重启

```
启动：systemctl start meeting-app        （或脚本 start.sh / start.bat）
停止：systemctl stop meeting-app         （停止前确认无进行中的导入任务）
重启：systemctl restart meeting-app
日志：journalctl -u meeting-app -f       （或 logs/ 目录）
```

## 五、初始化与账号管理

### 5.1 五角色账号（最小权限原则）

| 角色 | 对应人 | 初始账号 | 关键权限 |
|---|---|---|---|
| 一线专员 staff | 林亦舟 | lin | 登记/补录需求项 |
| 协调员 coordinator | 唐映秋 | tang | 定版、发起交接 |
| 业务负责人 biz_owner | 顾明岚 | gu | 确认签字、试点范围调整 |
| 质量验收 qa | 傅景 | fu | 质量签字、异常闭环、**暂停权** |
| 管理员 admin | 秦芮 | qin | 字段配置、导入、映射、脱敏规则、用户管理 |

首次登录强制改密；密码策略 ≥8 位含字母数字。**编辑权限与确认权限分离是系统红线，任何账号不得兼配两类角色（f22：模型/系统亦无审批权）。**

### 5.2 数据初始化顺序

1. 建批次（名称、计划项数默认 50——分批口径按 B5 确认结果调整）；
2. 导入/维护编号映射表（三源无统一编号，f30）；
3. 配置脱敏规则（B6 确认后；未确认前保持为空，敏感需求不入库）；
4. 灌入虚构演练样本做一次全流程演练，**演练数据批次标记 demo，与真实数据物理隔离**；
5. 删除演练批次或归档，开始真实登记。

## 六、上线流程与回滚

### 6.1 上线执行序（建议周四或周五执行，留周末缓冲）

```
D-1 日：完成 2.1 全部技术闸门 + 2.2 业务闸门核签；全量备份空库基线
D  日 09:00：停服窗口（预计 ≤30 分钟）→ 部署最终版本 → 初始化 → 冒烟复跑
D  日 10:00：五角色登录验证 → 创建真实批次 → 通知全员上线
D+1 日：值守观察（见 7.3），收集一线反馈
D+7 日：第一次周复盘（试点周报 #1，M1/M5 基线实测启动，R7）
```

### 6.2 回滚方案

| 场景 | 动作 |
|---|---|
| 部署后冒烟失败 | 回退上一版本包重启（保留新库文件，故障数据不覆盖备份） |
| 运行中严重故障（见 9.1 P1 级） | 停服 → 恢复最近一次备份（第 8 章）→ 降级为线下登记（Excel 模板，事后补录） |
| 数据入库错误 | **禁止直接改库**：通过异常队列走人工复核闭环，保留原行不清洗（f33） |

线下兜底模板随交付物提供，恢复上线后由协调员按双轨补录规则（f13：群消息/线下先发生，系统补录并记双时间戳）追录。

## 七、日常运行操作（谁、多久、做什么）

### 7.1 每日（值守人，约 10 分钟）

- 查看异常队列：有无超时未认领工单（SLA 时限按 B3 确认值）；
- 查看登录与导入日志有无异常报错。

### 7.2 每周（固定动作，合计约 1 小时）

| 动作 | 执行人 | 说明 |
|---|---|---|
| 三源数据导入 | 秦芮 | 接口未通期间每周 CSV 导入；导入后核对映射关联数 |
| 快照核对 | 秦芮 | 检查三源快照时间戳与状态（f35），异常记录转异常队列 |
| 周复盘会 | 唐映秋主持 | M6/M7 看板出数；M1/M5 线下采样登记；周报归档 |
| 备份核验 | 秦芮 | 确认每日备份任务成功、抽 1 份做恢复抽查 |

### 7.3 上线后首月加强期

前两周为基线实测期（R7）：M1 处理时长、M5 复核成本**只测不考核**，实测值书面确认后替换报价测算中的假设值。第 4 周做一次故障演练（第 9 章任选一个 P2 场景）。

## 八、备份与恢复

### 8.1 备份策略

| 对象 | 频率 | 保留 | 方式 |
|---|---|---|---|
| 数据库 meeting.db | 每日 02:00 自动 | 30 天滚动 + 每月末永久 1 份 | `sqlite3 meeting.db ".backup backup/meeting-$(date +%F).db"`（WAL 在线备份，不停服） |
| 三源快照/导入原件 | 随导入 | 90 天 | 目录级复制 data/snapshots、data/imports |
| 配置与密钥 | 变更即备 | 永久 | 密钥**不入明文备份**，纸质/密码库另行保管 |

每月末备份异地留存 1 份（网盘/另一主机均可）。

### 8.2 恢复步骤（演练过才算会恢复）

```
1. systemctl stop meeting-app
2. 确认故障库文件移走留存（勿覆盖，供事后分析）
3. 复制备份：cp backup/meeting-YYYY-MM-DD.db data/meeting.db
4. systemctl start meeting-app
5. 核对：看板 M6 数值、最近一次导入数据、异常队列状态
6. 停服窗口内的线下动作（交接/确认）按 f13 双轨补录追录
```

## 九、故障处理手册

### 9.1 故障分级与响应

| 级别 | 定义 | 响应 | 例子 |
|---|---|---|---|
| P1 | 系统不可用或数据错误风险 | 立即停服评估，30 分钟内决定恢复/回滚 | 服务起不来、数据库损坏、越权漏洞 |
| P2 | 功能受损有绕行方案 | 4 小时内响应，当日给出绕行方案 | CSV 导入失败、看板不出数、卡口误拦 |
| P3 | 体验问题 | 下一周复盘处理 | 展示样式、导出格式 |

### 9.2 常见故障速查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 无法登录 | 账号停用 / 密钥变更使旧 token 失效 | 管理员核对账号；密钥一旦变更全员重新登录（勿随意改 SECRET） |
| 交接被拦截 | 三要素不全（f20）或 open_items_count 与实际不符 | **这是正常拦截不是故障**；按提示补齐要素或如实填报未结项 |
| 定版被拒绝 | f24 双条件：存在未确认项或有效期未设 | 先完成确认签字（顾明岚），或调整有效期 |
| 导入报重复 | 同批次幂等命中 | 到映射表核对 external_no 是否已关联；确需覆盖走异常队列人工处理 |
| 数据库锁死 | 低概率写冲突 | WAL 模式下极少见；重启服务恢复，未提交事务自动回滚 |
| 读取三源失败 | 接口/凭据/网络 | 系统自动保留快照标记时间（f35），勿重试业务动作（S2），走 CSV 降级 |
| 看板数值异常 | 映射缺失或批次口径变化 | 核对编号映射表与批次设置；M6 分母以批次计划项数为准 |

### 9.3 暂停机制（S1–S5 停止判据的运行时落地）

**傅景拥有暂停权**，以下情形立即暂停对应功能或整批试点：无法确认版本或关键字段（S1）→ 入队暂停该项；读取失败不重试业务动作（S2）；口径争议（S3）→ 暂停相关统计；预算超支（S4）→ 暂停新需求只做修复；数据合规风险（S5）→ 暂停涉敏功能。暂停/恢复均需在异常队列留记录（谁、何时、原因、恢复条件）。

## 十、安全与合规运行要点

- **账号**：人员变动 24 小时内停用账号；离职交接期改为"只读观察"而非保留编辑权；
- **密钥**：JWT SECRET 泄露即全员登出并轮换；数据库文件目录权限仅服务账号可读写；
- **敏感数据**：嘉宾敏感需求（f52）未确认脱敏规则前**不入库**；导出报表含敏感字段前须经秦芮核对；
- **审计**：审计日志只增不改；管理员不得删除留痕（f44/f45）；每月抽查 5 条确认类操作的留痕完整性；
- **红线**：不写回、不开放外部接口（f32）；模型/系统永无审批权（f22）。

## 十一、验收与移交

1. **验收触发**：试点批次 50 项全部具备责任人与确认状态且变更可追溯（f02/f42），M6=100% 由看板复算确认；
2. **验收动作**：傅景按验收记录模板逐项核签；报价浮动结算指标（如适用）同步复核；
3. **移交清单**：应用包与部署脚本、数据库与全部备份、本手册与口径文档、映射表与脱敏规则配置、账号清单（密码另附）、未结开放项清单（R1–R7 最新状态）；
4. **接管培训**：管理员独立完成一次"备份→恢复演练 + 一次 CSV 导入 + 一次异常闭环"方可视为接管完成；
5. **质保期**：按合同约定（中档无独立质保期，试点陪跑即保障期；高档含 3 个月运维支持，期内 P1/P2 由实施方响应）。
