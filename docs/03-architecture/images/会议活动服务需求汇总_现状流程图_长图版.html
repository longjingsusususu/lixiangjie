阶段 01登记与发生主办方 → 一线
起点为什么在这里
需求不是"没登记"，而是同一件事情被记在两个地方。登记那一刻没人错，错在两条记录从此各自演化。
f01、f10
议程确认主办方 · 顾明岚
确认议程与特殊要求（双语、设备、场地）。临时变更多发生在这一步之后，但变更只通知到人，没有回写到清单。
f01f11
断点 1 · 同一嘉宾被两个人分别记录
设备需求与语言服务需求由不同人员分别记录，发生节点与受影响对象当时都没记。事后对不上时，无法在原记录里判断是谁漏了什么。
f10
嘉宾需求登记一线 · 林亦舟
设备、语言、餐饮分别走各自的表。设备与语言由两个人记，两边不知道对方改过；一位嘉宾对应两条互不相认的记录。
断点 1f10f31
群消息 / 纸面兜底一线 · 现场
现场来不及就先用群消息或纸面兜住，事后回系统补录。于是"回填时间"取代了"业务发生时间"，任何按时间排序的分析都会失真。
f13f34
时间失真
回填时间 ≠ 发生时间。按时间先后判断"谁先改的"，会把晚录误判成晚发生，责任判断随之反转。
f13、f34
阶段 02汇总与定版流程协调员 · 唐映秋
人工拼接
50 项来自不同人的表，格式各行其是。缺项靠口头补，补完没有回写来源位置，下一场又要重新问一遍。
f15、f20
汇总成 50 项清单协调 · 唐映秋
按现有交接记录的格式人工拼成一张表，50 项来自多张不同来源的表。缺项靠口头补齐，补齐后不标注来源位置。
f02f20f21
定版本协调 · 唐映秋
"有效期 + 确认状态"双条件口径已经存在，但谁改规则、多久复核一次，没有人定。实际执行时，判断哪份是最新版靠文件名。
断点 2f24f34
断点 2 · 规则一变，清单即失效
有效版本靠双条件判，但维护人与复核周期空缺。规则一变，责任清单随之失效，且不留失效痕迹——旧版仍会被当成有效版传下去。
f24、f34
阶段 03交接协调 → 供应商 / 执行团队
断点 3 · 三项要素缺失
要求列明最新版本、未确认事项、截止时间，实际常只发一条"已处理"。三要素一缺，责任就在这句话里断开了。
f23、f25
供应商交接协调 → 接收方
交接记录要求写明接收人、版本、未结项，但实际常只发一条"已处理"。接收方按自己理解执行，无从核对。
交接点断点 3f23
未确认项归属协调 / 接收方
规则是"未确认项不能归到对方名下"。于是它既不算我方、也不算对方，成为谁都不认领的无主区，随清单一起流到执行。
f25f31
无主区不等于推诿
这不是态度问题，是规则本身没有给这类项指定归属人。只要"确认"这个动作没有指定人，"无主"就是必然而非偶然。
f25
阶段 04执行与对外承诺供应商 · 业务人员
错版直达客户
执行发生在对外承诺之后。一旦版本错、漏项多，纠错成本已经不可撤销——这是全流程唯一"事后无法补救"的环节。
f42、f52
按原方案执行供应商 / 执行团队
按定稿版本交付。翻译、设备清单沿用原方案，现场临时改双语时不会自动回传，清单与实际开始分叉。
f10f11
对外承诺业务人员 · 人工确认
承诺由业务人员确认，模型与工具没有审批权。但"未确认"项若没被标出来，会被默认当成"已确认"一起发出去。
人工确认f22f52
不可撤销的一步
客诉、赔偿、信誉损失都发生在这一步之后。能拦的地方在交接（阶段 03），不在承诺（阶段 04）——这也是为什么切入点选 REQ-1 + REQ-3。
f42、f44、f52
阶段 05核对与回查数字化工程师 · 秦芮
无统一关联编号
服务台、台账、文件库各存一份，跨工具只能靠字段匹配。字段一改，历史记录就对不上，这是数据侧最担心的一点。
f30
跨三套工具核对数字化 · 秦芮
内部服务台、业务台账、文件库三处各存一份记录。没有统一关联编号，只能靠嘉宾名、日期、场次做字段匹配。
f30f31f32
异常回查原始版本协调 / 数字化
出问题后翻原始版本，判断哪一环没有同步。演练样本约 4 小时/场（虚构样本，不作基线），且没有登记入口，查完即散。
f11f12 虚构
现状没有"异常入口"
没有登记处、没有值守人、没有响应时限，也没有"不得默认通过"这条硬规则。异常只能由现场人员自行发现——这正是 REQ-3 要补的卡口。
f44
阶段 06验收与复盘审核质量 · 傅景 / 客户协同 · 叶书
唯一的硬验收
不看"效率提升了多少"，只看50 项是否每一行都有责任人和确认状态。这条口径是全流程唯一可判定的验收标准。
f02、f42
50 项质量验收质量 · 傅景
50 项服务项全部具备责任人与确认状态，变更影响可追溯，每条结果能追到来源与人工复核记录；达不到不签字。
人工确认f02f42
客诉登记与每周复盘客户协同 · 叶书
客诉先登记原始问题与版本，不推测客户意图；每周收集误报、漏报、未确认项，双方对齐口径后再谈工具。
f54f55f50
复盘能发现问题，但改不了流程
每周复盘是现状里唯一稳定的反馈回路，但它只记录问题、不指定责任人，也不触发流程变更——所以同样的问题会重复出现。
