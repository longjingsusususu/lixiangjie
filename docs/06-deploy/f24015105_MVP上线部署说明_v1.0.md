## 三、上线后的五条使用主线（对应测试场景）

1. **正常**：lin 登记需求项（双时间戳自动记录）→ guml 确认签字 → tang 建版本/定版 → tang 发起三要素交接 → lin 确认接收 → 看板 M6/M7 出数；
2. **边界**：留空描述、超长描述、错格式时间 → 系统返回显式中文错误码；
3. **对抗**：交接不填三要素 → 服务端拦截（"列明未结项与实际不符——不允许只报已处理"）；
4. **权限**：用 lin 试图确认签字 → 403；
5. **故障**：对脏数据项报异常 → fujing 认领并填结论闭环 → 原行保留不清洗（f33）。

## 四、安全与合规注意（演示环境边界）

1. 演示密码为公开种子数据，**仅用于功能演示**，生产部署前必须重置并替换 JWT 签名密钥（SECRET）；
2. 数据全部为 f12 虚构演练样本，不含任何真实客户信息；
3. 沙箱为单实例 SQLite，无异地备份：**演示环境产生的数据不承诺持久性**，正式试点按《上线交付运行手册》第 8 章执行备份策略；
4. 本链接为公开可访问的演示环境，勿录入敏感数据（嘉宾敏感需求脱敏规则 R6 确认前不入库的红线在演示环境同样适用）。
