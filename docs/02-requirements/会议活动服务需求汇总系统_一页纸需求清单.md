# 会议活动服务需求汇总系统 · 一页纸需求清单

> 需求评审问答（10 项）已自答并标注依据。依据：本项目访谈证据（f 编号）、业务挖掘成果（REQ-1~6、M1–M8、E-01）。版本 v1.0 · 2026-10-30

## 一、目标与范围（Q1/Q10）

**目标**：把"登记分散、版本靠猜、交接只发已处理"的现状（E-01，f23/f24），改造为"每项有责任人、有确认状态、有版本、有来源"的需求汇总系统，验收口径为 **50 个服务项全部具备责任人与确认状态且变更可追溯**（f42）。

| 一期做 | 说明 |
|---|---|
| ① 需求登记与汇总 | 单批次 50 项，双轨兜底（群消息先、系统补录，延续 f13 现实） |
| ② 版本定版 + 交接卡口 | 系统生成版本号，维护人手动定版；交接强制三要素（f20） |
| ③ 异常人工队列 | 缺项/冲突/脏数据入队，不得默认通过（f44） |
| ⑦ 统计看板 | M6/M7/M8 自动埋点，M1/M5 采样 |
| ④ 只读集成（待定→降级路径） | 三套工具只读聚合（f30/f32）；**接口开不了则降级为每周批量 CSV 导入** |

**二期**：⑤ LLM 需求抽取向导 + 制度问答（复用报销助手 RAG 架构）｜**不做**：⑥ 供应商侧入口；自动邀请真实嘉宾、发布会议安排、确认敏感个人需求、任何写回与外部接口（f05/f52/f32，永久不做清单）。

| 角色 | 对应人 | 权限 |
|---|---|---|

设计原则：**编辑权限与确认权限分离**，模型无任何审批权限（f22 红线）。

## 四、非功能需求

- **双时间戳**：每条记录区分业务发生时间与系统接收时间（f13/f34），表结构强制字段；
- **留痕四项**：谁查过、哪个版本、什么建议、谁确认（f44 要求）；
- **只读边界**：不写回、不开放外部接口；读取失败保留快照并标记时间（f35）；
- **暂停条件**：无法确认版本或关键字段进人工队列，必要时暂停，不得默认通过；
- **性能**：单批次 50 项、并发 ≤10 人，普通云主机足够，无需水平扩展。

## 六、风险与开放问题（访谈遗留待定项）

1. **三套工具只读接口能否开放**（Q8）——开不了则一期走 CSV 导入，集成模块顺延；
2. **版本规则维护人与复核周期**（REQ-2）——待顾明岚/唐映秋确认，阻塞 Q3 上线；
3. **异常队列值守人与响应时限、暂停恢复条件**（REQ-3）——待傅景确认，阻塞 Q5 上线；
4. **交接责任转移时点**（REQ-1）——两个口径未定，字段无法定稿，待顾明岚签字；
5. **M1 处理时长 / M5 复核成本基线全缺**——试点首周实测，不预填目标；
6. 敏感字段脱敏粒度与留存期限（f52/REQ-6）——待秦芮、傅景确认。

> 以上 6 项全部来自业务挖掘附录 A 的"执行层口径未核实"清单，属于**上线前置条件**而非可延后优化项。
