## 1. 接口总览

| # | 方法 | 路径 | 用途 | 鉴权 |
|---|---|---|---|---|
| 1 | POST | `/api/login` | 用户名密码 → JWT | 无 |
| 2 | POST | `/api/chat` | 提问，SSE 流式返回 | Bearer JWT |
| 3 | GET | `/api/sessions` | 我的会话列表（侧栏历史） | Bearer JWT |
| 4 | GET | `/api/sessions/{sid}/messages` | 单会话历史消息（含引用） | Bearer JWT |

鉴权两种来源：API 用 `Authorization: Bearer <token>`；SSR 页面用 `mt_token`（HttpOnly cookie）。
token 有效期 8 小时，每次请求回库校验角色与启用状态（改角色/停用即时生效）。

## 2. `POST /api/chat`

### 2.1 请求

```http
POST /api/chat
Authorization: Bearer <JWT>
Content-Type: application/json

{
  "session_id": "8f3c…（可 null，null 表示新建会话）",
  "question": "那餐饮呢？"
}
```

### 2.2 前置校验（全部在建立流之前完成，失败返回普通 JSON）

统一错误体：`{"code": 40001, "message": "问题不能为空"}`（HTTP 状态码与 code 同时给出，前端只认 code）

| 校验 | HTTP | code | message |
|---|---|---|---|
| 未登录 / token 失效 | 401 | 40101 | 未登录或登录已过期，请重新登录 |
| question 为空 | 400 | 40001 | 问题不能为空 |
| question > 200 字 | 400 | 40002 | 问题过长（上限 200 字） |
| 10 秒内第 6 次请求 | 429 | 42901 | 请求太频繁，请稍后再试 |
| session_id 不存在 | 404 | 40401 | 会话不存在 |
| session 属于他人 | 403 | 40301 | 无权访问该会话 |
| 检索索引未就绪 | 503 | 50301 | 检索索引未就绪，请联系管理员导入需求项 |
| 未捕获异常（流内） | — | 50001 | 系统繁忙，请稍后重试 |

### 2.3 响应：`text/event-stream`

| 顺序 | event | data 示例 | 前端行为 |
|---|---|---|---|
| 1 | `status` | `{"stage":"search","message":"正在检索需求项…"}` | 显示状态条 + 打点动画 |
| 2 | `item` ×N | `{"item_no":"LS-02","category":"语言服务","status":"未确认","content":"主持人临时改为中英双语主持","owner":"唐映秋","source_tool":"手工补录","source_ref":"群消息2026-10-24｜聊天记录","biz_occurred_at":"2026-10-24"}` | 追加一张清单卡片；**收到首条即收起状态条** |
| 3 | `chunk` ×M | `{"text":"共命中 3 项，其中未确认 2 项。"}` | 进打字机队列，逐字上屏 |
| 4 | `done` | `{"session_id":"…","message_id":128,"elapsed_ms":86,"citations":[{"item_no":"LS-02","source_tool":"手工补录","source_ref":"群消息2026-10-24｜聊天记录","snippet":"主持人临时改为中英双语主持"}]}` | 渲染引用区，解锁输入框 |
| 任意 | `error` | `{"code":50001,"message":"系统繁忙，请稍后重试（detail）"}` | 红色错误条，解锁输入框 |

原始帧格式（`data` 为单行 JSON，中文不转义）：

```
event: status
data: {"stage": "search", "message": "正在检索需求项…"}

```

**为什么仍用 SSE**：一期默认零 LLM，但「检索中 → 逐条出结果 → 汇总」的渐进感必须保留；二期接入 LLM 时前端零改动，只是 `chunk` 内容从规则文案变成模型输出。

### 2.4 落库时机（保证「问过什么」不丢）

1. 校验通过 → 建会话（如无）→ **先写 user 消息**（即使后续出错，痕迹仍在）；
2. 检索命中 → 逐条写 `audit_logs(action=view)`（f44「谁查过」）；
3. 流结束 → 写 assistant 消息（含 `citation_source_refs` JSON 与 `latency_ms`）。

## 3. `GET /api/sessions`、`GET /api/sessions/{sid}/messages`

```json
// GET /api/sessions  （按创建时间倒序，最多 50 条）
{"items":[{"id":"8f3c…","title":"双语主持相关的需求有哪些…","created_at":"2026-11-04 21:02:11","msg_count":4}]}

// GET /api/sessions/{sid}/messages  （时间正序，引用已解析成数组）
{"session":{"id":"8f3c…","user_id":1,"title":"…","created_at":"…"},
 "messages":[{"id":127,"role":"user","content":"…","citation_source_refs":"[]","latency_ms":null,"created_at":"…","citations":[]},
 {"id":128,"role":"assistant","content":"共命中 3 项…","citation_source_refs":"[{…}]","latency_ms":86,"created_at":"…",
  "citations":[{"item_no":"LS-02","source_tool":"手工补录","source_ref":"群消息2026-10-24｜聊天记录","snippet":"…"}]}]}
```

历史消息必须**带引用**返回，否则回看时无法复现「当时的依据」（验收口径）。

## 4. 数据表（SQLite，WAL）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | id / username / password_hash / display_name / role / is_active | 五角色枚举，staff 登录即用 |
| `chat_sessions` | id(uuid) / user_id / title(首问前 20 字) / created_at | 侧栏历史 |
| `messages` | id / session_id / role / content / `citation_source_refs`(JSON) / latency_ms / created_at | 引用随消息存，回看可复现 |
| `requirement_items` | item_no / category / content / status(五态) / owner / source_tool / source_ref / biz_occurred_at / received_at | 检索对象；双时间戳、缺失与未确认分列 |
| `audit_logs` | actor_id / action(view) / target_type / target_id / created_at | f44 留痕 |

索引：`messages(session_id, id)`、`chat_sessions(user_id, created_at)`、`audit_logs(actor_id, created_at)`。

## 5. 上下文策略（最近 N 轮）

当前实现：取本会话**最近 6 条消息**（≈3 轮问答），只用于**查询扩展**，不用于改写历史回答。

```python
# portal.py: _expand_with_context()
rows = SELECT role,content FROM messages WHERE session_id=? ORDER BY id DESC LIMIT 6
# 短问题（≤8 字）且历史里出现过类别词 → 拼进当前查询
# "那餐饮呢？" + ["餐饮"] → 命中 CQ-0x；长问题不补，避免污染检索
```

- **一期（规则版）**：补类别词，解决省略式追问；命中率提升见 `docs/04-agent` 评测用例第 5 组。
- **二期（LLM 版）**：这 N 条原样进提示词，接口与表结构不变。

> 提示词要求「6 轮」，当前代码是「6 条」。差异见 §7 决策 2。

## 6. 前端单页规格（`app/static/index.html`，HTML + 原生 JS，单文件）

```
┌──────────────────────────────────────────────┐
│ 会议活动需求查询台              [林亦舟 · 退出] │
├──────────┬───────────────────────────────────┤
│ 历史会话  │ [我] 双语主持相关的需求有哪些？      │
│ ·XX年会   │ ⏳ 正在检索需求项…                 │
│ ·10月周会 │ ┌───────────────────────────────┐ │
│          │ │ LS-02 语言服务 [未确认]         │ │
│          │ │ 主持人临时改为中英双语主持        │ │
│          │ │ 责任人 唐映秋 · 来源 群消息10-24 │ │
│          │ └───────────────────────────────┘ │
│          │ 共命中 3 项，其中未确认 2 项。▌     │
│          │ ── 来源 ───────────────────────   │
│          │ ① LS-02 手工补录｜群消息2026-10-24 │
│          │ ② EQ-05 服务台｜SD-2026-0118｜第12行│
│          ├───────────────────────────────────┤
│          │ [ 输入问题…                  ] [发送]│
└──────────┴───────────────────────────────────┘
```

| 要点 | 实现方式 |
|---|---|
| SSE 解析 | `fetch` + `ReadableStream` 手动按 `\n\n` 切帧，解析 `event:` / `data:`（不依赖 EventSource，因其不支持自定义 header） |
| 打字机 | `chunk` 入队；`setInterval` **18ms/字** 上屏；`done` 时等队列清空再解锁 |
| 状态条 | `status` 显示 + CSS 三点动画；首个 `item` 到达即隐藏 |
| 引用区 | `done.citations` → 「来源工具｜单据号｜行位置」+ 片段；条目用序号对齐 `item` 卡片 |
| 错误处理 | `error` 事件与非 2xx 统一红色横条，显示 `[code] message`；输入框与发送按钮解锁 |
| 并发保护 | 请求中禁用发送按钮，避免同一会话并行写 |
| 历史回看 | 侧栏 `/api/sessions`；点击 `/messages` 重建气泡与引用 |
| token | `localStorage` 存 `mt_token`，401 时清除并回登录 |

## 7. 需要你确认的 4 个差异

| # | 差异 | 现状 | 建议 |
|---|---|---|---|
| 1 | 路径 `/chat` vs `/api/chat` | 代码为 `/api/chat` | **保留 `/api/chat`**；若要求字面一致，加 `POST /chat` 307 别名（3 行） |
